# 状態管理・既存帳票・計画の接続

## 完成時の役割

| 場所 | 扱うもの | 更新の扱い |
| --- | --- | --- |
| アプリ | 現在の状態、径、使用期間、履歴、工作への組替指示 | 対応する管理項目を表計算と双方向反映 |
| 既存ロール管理のペア別シート | 従来の配置・色・結合・計算・履歴・印刷書式 | 原本を保持し、対応セルだけ読み書き |
| Roles | アプリと履歴表を結ぶ現在状態 | 表の行番号ではなくロールIDで対応 |
| 月間ロールカリバ替予定 | 生産予定に対応する交換・改削・組替の原案と採用結果 | 元の月間帳票を使う。原案と採用済みを区別 |
| 年間計画 | 改削・購入・払い出しと予備の将来見通し | 月間計画と実績を参照。未確認の納期は未確認のまま |
| 工作課ボード | 採用された組替対象、期限、進捗 | 未採用の計画候補を指示扱いしない |

ロールカリバ替予定・年間計画の閲覧画面をアプリへ追加しない。現行のExcel読込・シート出力操作は移行中の入口として存在する。表計算側の入口が整った段階で役割を整理する。

## 初回コード確認

基準コミット: `8117ea2`。コード上の実装と本番確認は別に扱う。

| 要件 | 現状 |
| --- | --- |
| 状態・履歴・組替指示期限 | Rolesの16列とアプリ間の読み書きあり |
| 従来のロール管理表 | 8組のシートを丸ごとコピーする移行処理あり。表をRolesから再生成しない |
| 履歴表のステータス | 表の帯とRolesの連携あり。編集トリガーが必要 |
| 搬出・搬入・径・使用開始・終了 | 対応する現在サイクル行との双方向処理あり。適用項目はスタンド定義に従う |
| 業者、材質、硬度、過去全サイクル等 | 従来の表に保持。すべてがアプリ編集項目とは限らない |
| 同時更新 | 既存は行全体の更新時刻で選択。この変更で取得後のサーバー更新を検出して保存停止 |
| 月間出力 | 既存テンプレートのコピー、日付・班・サイズ・サイズ替候補の出力あり |
| カリバ・ロール交換の総合計画 | 汎用の候補計算まで。現場の全制約・残量・将来在庫との統合は未完成 |
| 年間計画・月々の改削 | 統合された計画・再計算フローは未完成 |
| 採用した月間計画から工作指示 | 工作側の選択・期限管理はあるが、計画からの採用履歴付き接続は未完成 |
| 原本との表示・印刷一致 | コピー実装はあるが、実Google Sheets・印刷での差分確認が必要 |

更新時刻が異なるオフライン変更は、まだ従来の行単位の選択を行う。今回のrevision保護は「取得後～保存前」の変更を対象とし、項目単位の三者比較や競合解決画面の完成を意味しない。

## 今回の変更

- GETで返したRoles内容のハッシュを保存要求に添付し、同じスクリプトロック内で照合する。不一致なら全件保存を止める。古いクライアントからのrevisionなし保存も拒否する。
- no-cors POSTの完了を、要求ごとのIDで照会する。別端末の保存診断を自身の成功とは扱わない。
- 工作の組替期限も通常同期を経由する。保存結果を確認してから完了表示する。
- シート全消去をやめ、検証・行生成の後に管理対象列のみ書く。削除で余った管理列の行だけ消す。
- 月間テンプレートは名前の前後差・中黒・空白・年月だけの名前に対応。ただしヘッダー配置の一致が必要。
- 同月の候補なら移行元より運用先を優先。短い月の存在しない日への繰越・提案を除外する。
- 月間原案の日付・サイズ・班・年月が手修正されたら、再出力で上書きしない。旧方式の原案は比較元がないため停止する。
- テンプレートに前回の自動提案の注記がある場合、コピー側で解除してから次月を生成する。

ロックはスクリプト間の排他であり、人がシートを直接編集する操作自体を止めない。比較直後の直接編集、未実行の履歴表編集トリガー、複数シートにまたがる失敗には別の対策が必要。保存前の履歴照合と、保存後の一部未反映通知・再試行記録を追加した。表を直接編集したときの失敗通知は引き続き改善対象。

## 接続するデータと更新ルール

1. ロールID、改削／交換サイクルID、カリバID、操業日・勤、計画版、原案／採用状態を別項目で保持する。
2. 計画使用量と実績使用量を分離する。同じカリバの再使用を累計し、同時使用ペアの各カリバに使用量を加算する。操業量自体は重複計上しない。
3. 既存帳票のセル対応は設定で管理し、結合範囲の左上セルに対象値だけ書く。帳票の全面clearや再描画はしない。
4. 月間原案には根拠・不足情報・変更差分を付ける。採用は別の確定操作とし、その版から組替指示を作る。同一採用IDで再実行しても指示を重複作成しない。
5. 採用済み計画が変わったときは、その計画に由来する期限・指示への影響を示す。手動の指示を黙って書き換えない。
6. 年間計画は月間の必要量、径・残回数、予備状態、確定した改削／調達期間を参照する。未知の使用量・納期をゼロや一律日数に置き換えない。
7. 現場固有の寸法、許容差、使用上限、ロール配置、生産量、業者・金額は非公開の設定・資料に保持する。

## 次の作業順

2. 同期成功時の基準スナップショットを持ち、同じ項目への両側変更を保留する。履歴サイクルとセル対応を安定ID化し、反映の失敗をアプリ・シートへ示す。
3. 「ロール管理」「ロールカリバ替予定」を原本と並べ、結合・列幅・行高・色・数式・改ページ・印刷範囲を確認する。テンプレートの右側カリバ図や前月の注記は、コピーだけでは当月の計画として正しくならない。未接続項目を明示して別に更新設計する。
4. 既存予定を再現・照合する非公開の配置・使用量・制約マスタをつなぎ、月間計画と月々の改削計画を作る。
5. 採用版から工作への指示を接続し、実施実績から再計算する。
6. 年間の改削・購入・払い出しへ広げる。

## 配布と検証

この変更はフロントエンドとGASの同時更新を前提とする。新版クライアント＋旧GASはrevisionがないため送信停止、新GAS＋旧クライアントも保存拒否になる。検証環境で両方を切り替えてから本番展開する。

NodeテストはGAS APIのモックを含む。実トリガーの設置、本番デプロイ、通信、Sheetsの書式・印刷が動作することの証明にはならない。

## 実Google環境での検証入口

`test/manual-gas-validation.gs` は非公開の検証用コピー専用。通常のGASに追加しない。
検証用ファイル名を `検証用_` で始め `実運用禁止` を含め、コピーのIDを
`ROLL_MANAGEMENT_SPREADSHEET_ID` と `ROLL_VALIDATION_SPREADSHEET_ID` の両方に設定する。
異なるID・通常のファイル名では実行を止める。IDは公開コードへ記載しない。

- `runValidationReadOnly`：実シートの件数、revision生成、8組の履歴ブロック検出を確認する。
- `runValidationStaleSave`：検証用Rolesのメモ1セルを一時変更し、古いrevisionの保存拒否と元の値への復元を確認する。実行前に他の編集・トリガーが動いていないことを確認する。
- `runValidationCycleAudit`：使用中の候補と表の現在サイクルを読み取り照合する。終了予定の記載を終了実績と混同しない。
- `runValidationDateRoundTrip`：開始日が一致する使用中サイクルを1件選び、revision付き保存で開始日を翌日に訂正して同じ履歴行への反映を確認する。表を元の日付へ戻し、編集ハンドラーを明示呼出しして逆方向の反映と同一イベント再処理時の履歴重複防止を確認する。finallyで元のRoles・対象ブロックの値、数式、文字色、背景、ノートを復元・照合する。実行中は他の編集・トリガーを止める。

書き込み前の読取が60秒を超えた場合は、復元時間を確保するため変更せず停止する。
ただし実行時間上限で強制終了されるとfinallyの完了は保証できない。実行前に対象の
Roles行と履歴ブロックのバックアップを別途保持し、失敗時は残存差分と元のrevisionを
照合して復元する。変更後に本番側の値を丸ごと取り直して上書きしてはいけない。

これは実ブラウザの同期通信・実編集トリガー・帳票印刷の検証を代替しない。
初回OAuthの承認待ちは未実行として記録し、配置成功を動作成功と扱わない。

月間帳票の交換指示の括弧内は、交換後に使うカリバ番号を示す。
ロール替とカリバ替を別の作業として保持し、使用直数やロール番号と混同しない。

## 再開後の同期検証と空欄訂正

- 非公開コピーに編集トリガーを設置し、実際のSheets画面から日付を訂正・空欄化した。自動実行の完了とRolesへの反映を確認し、対象セルを復元した。
- アプリ保存処理で非空欄から空欄へ訂正したとき、同じID・ステータスの変更前値と現在サイクルの実績が一致する場合だけ対象セルを消す。予定色、他サイクル、照合できない値は消さない。
- 履歴への対応を保存前に試算し、競合・未対応欄があればRolesの保存前に停止する。保存後の障害は`partial`として返し、クライアントが同期成功と表示しない。
- 履歴への未反映が残ったときは、変更前情報をScript PropertiesへロールIDごとに保持する。次の保存で変更がなくても再照合・再反映する。別途訂正、削除、運用対象解除があれば自動処理を止める。正常反映後に保留記録を消す。
- `runValidationDateRoundTrip`に空欄訂正・隣接終了日の保護・未反映記録の解消確認を追加。実Google環境で往復訂正、空欄反映、重複防止、値・書式の復元まで成功した。
- 自動テスト112件成功。実アプリ画面のPOST・結果照会、オフライン競合、全履歴サイクル、全帳票の印刷一致は未確認。本番へは反映していない。

`runValidationPlanningDraft`は検証コピーだけに当月の暦と検証文言を出力する。実生産予定の再現ではない。コピー元の結合・列幅・行高、繰越、再出力の重複防止、手修正保護を調べる。前月の右側図・注記、月の日数に応じた罫線・色、Excelとの印刷一致は別途確認する。

この検証は実Google環境で成功した。元シートは不変で、コピー元と結合・列幅・行高が一致し、繰越予定が残り、再出力は同じ1シート・同じ提案になり、日付の手修正を検出して保存を停止した。
画面確認で、30日月のひな形から31日月を作ると最終日の罫線・結合が不足する問題を発見した。新規コピー時に不足する日だけ元の通常日の書式・結合・行高を補完し、別用途の結合は変更前に検出して停止する処理を追加。実Google環境で1日分の補完、値の不変、3組の結合・行高・罫線を確認した。2月から31日月、短い月、想定外の結合を含め自動テスト116件成功。

作成日・右側の図や注記は前月のまま残るため、右側は転記元の参考情報であることを自動案に表示する。通常のGoogle印刷は右側まで含めて縮小するため、元Excelの印刷範囲と一致しない。業務用としての採用・印刷の自動設定は引き続き未完成。


### 月間表の印刷入口（コード検証済み・実画面未確認）

スプレッドシートに紐づくGASでは、開き直すと「ロール帳票 → 月間予定をPDF表示」を利用できる。年月名と見出しを確認した月間表に限り、B1:M40をA4縦・幅合わせでGoogleのPDF出力へ渡す。右側の参考図を除外し、共有権限・セル・印刷済み状態を変更しない。自動案は採用済みではないとダイアログに表示する。

URLはGoogle公式サンプルのPDF出力パラメーターを使用する（https://developers.google.com/apps-script/samples/automations/generate-pdfs）。これはSheets標準印刷設定の書換えではない。改ページ・原本との完全一致、メニューからの実PDF表示は未確認で、本番・検証GASにはこの入口をまだ配置していない。ローカルで対象範囲・不正ID拒否・別シートでの停止を確認し、既存116件も成功した。
